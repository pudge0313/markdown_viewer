# Markdown 查看器 · 功能差距分析与需求池

> 版本基线：v1.1.0（commit `aac1ab6`）｜分析日期：2026-11-14
> 分析对象：`E:/markdown_viewer`（Electron 33 + marked 14 + highlight.js 11.10，只读预览器）

## 一、一句话结论

**这个产品不缺功能数量，缺的是"阅读器本分"的四件事：搜不到、找不到、看不全、跳不通。**
文档内搜索、大纲导航、代码块复制、图片放大——这四项在 Typora / Obsidian / VS Code 预览 / Marked 2 里**全部具备**，属于品类门槛而非加分项。先把这四项和三个真 bug 补掉，编辑类功能一律不做。

> 判断依据：一个只读查看器的护城河是"双击就能舒服读完"，不是"能改"。一旦加编辑，就进入 Typora（免费版可用）/ VS Code（已装）的正面战场，个人维护量级打不过。

## 四、三个必须承认的硬伤（bug 级，不是功能）

这三条不是"缺功能"，是"承诺了但没做到"，优先级高于所有新功能。

### 硬伤 1：文档内 `../` 相对链接必然打不开

【事实】`app.js:398-401` 的 `joinPath()` 只做字符串拼接不归一化；点击后 `readFile` 落到 `guard.js:15-16`：

```js
const segs = norm.split(/[\\/]/);
if (segs.includes('..') || segs.includes('.')) return null;
```

路径里带 `..` 直接被判非法 → 用户看到"仅支持打开本地 Markdown 文件"。而同一文档里的图片 `../img/a.png` 却能正常显示（走 `file://` 由 Chromium 自行归一化）。

**同一份文档，图能看、链接跳不过去**——这是最伤信任的一类不一致。修法：跳转前在渲染进程用 `path` 归一化（或主进程改用 `path.resolve` 后重新走守卫校验）。

### 硬伤 2：外部修改无法感知为"即时"，且大文件会拖慢

【事实】`app.js:243-257` 每 2 秒 `readFile` + 全量 `renderMarkdown` + 字符串比对 + `innerHTML` 整体替换。

- 空转成本：即使文档没变，也每 2 秒读盘 + 完整重解析一次；
- 大文件（>1MB）解析耗时可观，且全量替换导致**滚动位置、图片加载、代码块状态全部重建**；
- 文件被删除/占用时 `readFile` 返回 `ok:false`，代码里没有分支 → 静默无提示。

**修法**：主进程 `fs.watch` + 200ms debounce，只推 mtime/size；渲染进程比对 mtime 再决定是否重解析。

### 硬伤 3：打开对话框允许选"所有文件"，但选了必然失败

【事实】`ipc.js:36-38` 的 filters 含 `{ name: '所有文件', extensions: ['*'] }`，而 `guard.js:17` 只放行 4 种扩展名。用户选一个 `.txt` → toast "仅支持打开本地 Markdown 文件"。

**要么去掉该过滤器，要么支持 `.txt/.mdx` 只读**（推荐后者，顺手扩大适用面）。

**顺带（同一类"宣称与实现不一致"）**：README 说"排版对齐 VS Code 的 Markdown 预览"，但 `preload.js:37` 开了 `breaks: true`，而 VS Code 预览默认 `markdown.preview.breaks: false`。**假设**：这是有意为中文文档保留软换行；若是，请在 README 注明差异，否则应默认关闭并给开关。

## 五、需求池 + RICE 评分

### 5.1 口径说明

- **Reach**：每月会用到该能力的用户占比（估算 0–100）
- **Impact**：3 = 质变，2 = 显著，1 = 有感，0.5 = 轻微
- **Confidence**：对 Reach/Impact 判断的信心
- **Effort**：人日，含自测，不含打包（估算）
- **RICE = R × I × C ÷ E**

> **数据纪律**：下表 Reach / Impact / Effort **全部为估算**，无真实用户数据支撑——本项目为单人自用工具，没有埋点。请把这张表当作"排序脚手架"，不要当作测量结果。

| 假设 | 若假设变化 | 影响 |

## 六、MoSCoW 取舍

### Must —— v1.2.0「能读」（约 8.5 人日）

| 项 | 说明 |
|---|---|
| 文档内搜索 | 高亮、计数、上/下一个、Esc 关闭；不做正则替换 |
| 大纲侧栏 | 二~四级标题、当前章节高亮、点击跳转、与文件树切换 |
| 代码块一键复制 | 悬停出现，复制成功 toast |
| 图片点击放大 | 遮罩层 + 滚轮缩放 + Esc 关闭 |
| `../` 链接修复 + 对话框过滤器修正 | 见第四节 |
| fs.watch 替代 2s 轮询 | 保留"变化才重渲染"，顺带修删除文件静默 |
| 侧栏定位当前文件 | 打开文件时自动展开并高亮 |

### Should —— v1.3.0「好用」（约 11 人日）

打开文件夹作为工作区 · 多标签/多窗口 · 导航历史 · 阅读设置面板 · 阅读进度条 · 侧栏过滤与展开记忆 · 便携版 · 主题跟随系统

### Could —— v1.4.0+「加分」

KaTeX · Mermaid · 打印/导出 PDF · 表格 sticky 表头 · 快捷键面板 · 自动更新 · 大文件性能

### Won't —— 明确不做（附理由）

| 不做 | 理由 |
|---|---|
| **所见即所得编辑** | 正面战场是 Typora（免费可用）/ VS Code（已装）。只读是安全资产：不改用户文件，就永远不会弄坏用户文件 |
| 双链、知识图谱、标签体系 | Obsidian 的地盘，做不出差异，且需要重构整个数据模型 |
| 插件系统 | 单人维护插件 API 的成本高于收益；要扩展就改源码 |
| 云同步、协作 | 涉及账号、存储、合规，与"本地只读"定位冲突 |
| AI 摘要/问答 | 需联网 + 密钥 + 成本，且 `connect-src 'none'` 的 CSP 是刻意设计 |
| 移动端 | 场景不存在（手机上没人存 .md） |

### 12.3 实施中额外发现并修复的问题

1. **标题锚点其实一直是失效的**：marked v14 不再自动生成 heading id，原来的 `[x](#标题)` 与文档内锚点全都跳不动。现由渲染管线自建 slugger（中文保留、重名追加 `-1`）。
2. **中文文件名链接打不开**：marked 会百分号编码 href，未解码就拼路径会得到 `%E5%8F%82...` 这种不存在的文件。
3. **拖放打开在 Electron 32+ 已失效**：`File.path` 被移除，必须用 `webUtils.getPathForFile()`。已补 preload 通道。
4. **`file://` 下 `navigator.clipboard` 不可用**：复制按钮原本会静默失败，改走 Electron `clipboard`。
5. **侧栏并发刷新**：`setOpen` / `setMode` / `revealPath` 同时触发刷新时，同一文件会在树里出现 2–3 次。改为串行 + 游离节点渲染后整体替换。
6. **隐藏窗口不重绘**：截图工具在 `show:false` 下滚动截图永远是首屏——这是工具坑，已写入 `tools/shot.js` 注释。
